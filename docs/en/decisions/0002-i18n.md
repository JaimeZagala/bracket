# 0002 — Interface translation system

- **Status:** accepted on 2026-10-15 (Phase 1, step 3), as the approved plan says: "choose the library by measuring its size impact".
- **Measurement context:** Rust 1.99.0, workspace release profile, minimal program that already includes `toml_edit` (like `bracket.exe`).

## Requirements

- Spanish (default and reference) and English, chosen by the user.
- One file per language, loaded by a single module.
- No visible text hard-coded; every new text in both languages.
- The same system will serve the command line and the update notes.

## Options measured

| Option | Added size | Notes |
|---|---|---|
| Own TOML catalogs (read with `toml_edit`) | +7.5 KB | `toml_edit` is already in the exe for the configuration. Plurals and placeholders are handled in code |
| rust-i18n 4.2.4 | +45 KB | YAML embedded through macros; a missing key silently returns the key itself |
| fluent-bundle 0.16 | +199 KB | Full plural rules for every language (CLDR) and selectors; parses `.ftl` files at run time |

## Decision

**Own TOML catalogs:** `crates/bracket-ui/locales/es.toml` and `en.toml`, embedded in the exe and parsed on first use.

- Code asks for each text through a typed method (`texts.untitled()`, `texts.open_failed(error)`), so a typo does not compile.
- Tests fail if the two catalogs do not have exactly the same keys and placeholders (`{error}`), or if a method does not find its key.
- Plurals use separate keys (`more_warnings_one` / `more_warnings_many`). That is enough for Spanish and English.
- The language switches at once from the status bar and is saved in `config.toml`.

## Consequences

- Adding a text: the key in `es.toml` and `en.toml`, a method in `i18n.rs`, and its line in the `every_method_finds_its_key` test.
- If languages with more complex plurals (e.g. Polish or Russian) are ever added, fluent would be the option; the rest of the code would not change because it only uses the `Texts` methods.
